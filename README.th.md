# system-design-katas

[English](README.md) · อยู่ในซีรีส์ katas เดียวกับ [staff-katas](https://github.com/nuttakulsv/staff-katas) และ [incident-katas](https://github.com/nuttakulsv/incident-katas)

อ่านคู่มือ system design ทำให้รู้คำตอบ แต่การสัมภาษณ์วัดว่าเราหาคำถามที่ใช่เจอหรือเปล่า

system-design-katas ทำให้ AI agent กลายเป็นคนสัมภาษณ์ system design โจทย์แต่ละข้อตั้งใจให้กำกวมเหมือนการสัมภาษณ์จริง และคนสัมภาษณ์จะซ่อน requirement ไว้ ถ้าเราไม่ถามให้ถูกจะไม่ได้รู้ พอทำไปได้ครึ่งทางจะมีโจทย์พลิกมาทดสอบ design ของเรา จบแล้วได้ debrief ที่ปรับตามระดับที่เลือก (senior, staff หรือ principal) มีคำพูดของเราเป็นหลักฐาน, บอกว่า requirement ไหนที่เราพลาด, ผลว่าผ่านหรือไม่ผ่าน และตัวอย่าง design ที่ดีหนึ่งแบบ

## หน้าตาตอนเล่น

```
คุณ:    ขอโจทย์ขายบัตรคอนเสิร์ต ระดับ staff

Agent:  "คอนเสิร์ตใหญ่จะเปิดขายบัตรพรุ่งนี้ 10 โมงเช้า ช่วยออกแบบระบบขายบัตรหน่อย"
        เริ่มได้เลยครับ

คุณ:    มีกี่ที่นั่ง คาดว่าจะมีคนเข้ามากี่คน และครั้งที่แล้วมีปัญหาอะไร
Agent:  [2 นาที] 50,000 ที่นั่งแบบระบุที่นั่ง คนรอประมาณล้านคนตอน 10 โมง
        ครั้งที่แล้วบอทซื้อไปเกือบหมด และเว็บล่ม
  ...
Agent:  [31 นาที] ขายไปได้ครึ่งทาง ระบบจ่ายเงินช้าลง กว่าจะยืนยันได้ใช้ 3 นาที
        ที่นั่งที่จองค้างไว้จะเป็นยังไง
  ...
ผล: Hire (staff)
requirement ที่พลาด: การจ่ายผ่าน PromptPay ยืนยันผ่าน callback ของธนาคาร
บางครั้งมาหลังจากที่การจองหมดเวลาแล้ว design ของคุณจะขายที่นั่งเดียวกันซ้ำ...
```

## รายการโจทย์

| # | โจทย์ | จุดยาก (ไม่สปอยล์) |
|---|---|---|
| 01 | ขายบัตรคอนเสิร์ต | คนเป็นล้านเข้ามาตอน 10:00:00 |
| 02 | ledger ของ e-wallet | เงินต้องไม่งอกและไม่หาย |
| 03 | ย่อลิงก์ | ไม่ใช่ข้อที่คุณเคยซ้อมมา |
| 04 | ระบบแจ้งเตือน | ทีมอื่นจะเอาไปใช้แบบที่คุณไม่ได้คิดไว้ |
| 05 | จับคู่คนขับรถ | รถติดกรุงเทพฯ และพิกัดคนขับเข้ามา 50,000 ครั้งต่อวินาที |
| 06 | LLM gateway | ยี่สิบทีม ห้า provider งบเดียว |
| 07 | เอกสารที่แก้พร้อมกันหลายคน | ห้าสิบคน กับมือถือที่ออฟไลน์อยู่ |

ไฟล์โจทย์อยู่ใน [`skills/system-design-katas/prompts/`](skills/system-design-katas/prompts) และมี requirement ที่ซ่อนอยู่ อย่าเปิดอ่านก่อนเล่น

ตัวโจทย์เขียนเป็นภาษาอังกฤษ แต่ถ้าคุยกับ agent เป็นภาษาไทย มันจะสัมภาษณ์และ debrief เป็นภาษาไทยให้

## แต่ละระดับต่างกันยังไง

โจทย์เดียวกัน วัดผลสามแบบ

- **Senior:** design ที่ใช้งานได้ กลไกหลักถูกต้อง และเลือก trade-off อย่างมีเหตุผล
- **Staff:** หาจุดยากเจอเองโดยไม่ต้องมีใครบอก คุมทิศทางการคุยได้ และครอบคลุมเรื่องตอนระบบพัง การดูแลระบบ ค่าใช้จ่าย และการเติบโตของระบบ
- **Principal:** ตั้งคำถามกับตัวโจทย์เอง โยงกับธุรกิจ และมองเห็นผลกระทบระยะยาวทั้งต่อองค์กรและระบบ

## ใช้ทำอย่างอื่นได้ด้วย

- **รีวิว design จริง:** เอา design ของเรามาให้ agent รีวิวแบบ staff engineer ที่ช่างสงสัย โดยให้มันสร้างข้อจำกัดซ่อนที่เข้ากับธุรกิจของเรา
- **เป็นพี่เลี้ยง:** เล่นโจทย์กับน้องในทีม แล้วนั่งคุยเรื่อง debrief ด้วยกัน
- **คนสัมภาษณ์:** ใช้ปรับมาตรฐานคำถามและ rubric ของตัวเอง
